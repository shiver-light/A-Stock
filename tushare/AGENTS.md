# Tushare 接口使用规则

本项目的数据源允许使用 Tushare Pro。
默认假设：仓库运行环境已具备可用的高权限 token。

---

## 1. 文档来源规则

agent 在使用 Tushare 接口前，必须优先查阅 Tushare 官网文档，不得凭记忆臆测接口名、参数名、字段名或权限要求。

优先参考：
- 数据索引页（用于查找全部接口分类）
- 具体接口文档页（用于确认参数、字段、限量、权限）
- 权限/积分说明页（用于确认接口访问门槛和频次限制）

---

## 2. 接口选择规则

能用基础接口解决的问题，不要优先使用高成本或特色接口。

优先顺序：
1. 基础信息类接口
2. 常规行情 / 财务 / 因子研究所需接口
3. 特色接口
4. 分钟级或独立权限接口

如果某个任务可由多个接口实现，优先选择：
- 权限要求更低的接口
- 单次返回更大的接口
- 更适合批量拉取和本地缓存的接口

---

## 3. 权限与频次规则

agent 必须检查每个接口文档中的：
- 最低积分要求
- 是否属于独立权限接口
- 单次最大返回行数
- 推荐调用方式

注意：
- Tushare 的权限分为“积分接口”和“独立权限接口”两类
- 高积分通常意味着更高每分钟频次
- 分钟数据、部分特色数据、港美股等权限不完全等同于普通积分权限，可能需要单独开通
- 即使具备高权限，也应避免不必要的高频重复拉取

---

## 4. 批量拉取规则

对于全市场或长历史区间数据：

- 优先分批拉取
- 优先按 trade_date / end_date / start_date / ts_code 做切片
- 不要一次请求超出接口单次上限
- 大规模研究任务优先落地到本地缓存或数据库，不要每次实时重拉

如果某接口文档提示“建议保存到本地后使用”，则遵循该建议。

---

## 5. token 安全规则

禁止在代码仓库中硬编码真实 token。

必须优先使用：
- 环境变量
- `.env`
- 本地配置文件（加入 `.gitignore`）

示例：
- `TUSHARE_TOKEN`
- `os.getenv("TUSHARE_TOKEN")`

不得：
- 将 token 写入公开仓库
- 在日志中打印完整 token
- 在报错信息中暴露 token

---

## 6. SDK 使用规则

默认优先使用 Python SDK。

推荐初始化方式：
- `ts.set_token(...)` 后 `ts.pro_api()`
- 或直接 `ts.pro_api(token)`

agent 在生成代码时，应优先：
- 使用明确的字段列表 `fields=...`
- 限制返回列，避免无意义的大宽表
- 对循环调用增加节流、重试和异常处理
- 对批量采集任务增加断点续传或增量更新逻辑

---

## 7. 数据使用规则

对于量化研究和回测：

- 股票列表、交易日历、复权方式、财务披露时间必须显式处理
- 不得因接口方便而忽略披露日期或时间对齐
- 不得把“接口拿得到的数据”直接当作“当时可用的数据”

特别注意：
- 财务字段要考虑公告/披露时间
- 股票池历史成分、ST、停牌、退市处理要与策略假设一致
- 复权行情的口径必须与回测假设一致

---

## 8. 性能与稳定性规则

agent 应优先生成“可长期运行”的采集逻辑：

- 本地缓存
- 增量更新
- 重试机制
- 限流机制
- 请求失败后的恢复机制

避免：
- 在研究主流程里对同一数据反复联网请求
- 对全市场数据逐股票逐日期做低效双重循环请求
- 无字段筛选地拉取超宽表

---

## 9. 常用接口使用约定

基础信息：
- 股票列表优先使用 `stock_basic`
- 交易日历优先使用 `trade_cal`

行情：
- 常规日线优先使用 `daily`
- 涉及复权时优先明确使用 `pro_bar` 及复权口径

研究代码中，接口名、权限要求、关键字段应在注释或文档中注明来源页。

---

## 10. agent 行为约束

agent 不应：
- 凭记忆捏造 Tushare 接口
- 默认所有接口都可无限访问
- 在未确认权限前直接设计依赖高门槛接口的主流程
- 硬编码 token
- 在无缓存前提下重复抓取大规模历史数据

agent 应：
- 先查官网文档再编码
- 明确接口权限和限量
- 优先设计本地化数据层
- 对高频/批量调用加入节流和缓存
