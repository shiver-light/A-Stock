# 数据处理规则

本目录用于数据获取、清洗、预处理和缓存。

适用于：

行情数据
财务数据
指数数据
股票池数据
交易日历

---

# 1. 时间索引规则

所有时间序列数据必须：

按时间排序

示例：

sort_values(by="trade_date")

禁止：

未排序数据直接参与 rolling 计算。

---

# 2. 复权方式一致性

必须明确：

是否使用：

前复权
后复权
不复权

回测与因子必须使用一致口径。

不得：

混用复权与未复权价格。

---

# 3. 停牌处理

停牌期间：

价格可能不变
成交量为0
无法交易

策略若涉及交易可行性：

需考虑停牌影响。

避免：

假设停牌期间可正常买卖。

---

# 4. ST股票处理

若策略涉及股票池过滤：

需明确：

是否剔除 ST

不得：

隐式过滤或隐式保留。

---

# 5. 股票池历史一致性

股票池需避免：

幸存者偏差（survivorship bias）

例如：

使用当前成分股回测历史。

应优先使用：

历史成分数据。

---

# 6. 缺失值处理

必须明确：

缺失值处理方式：

drop
fill
forward fill
zero fill

禁止：

隐式填充。

示例：

fillna(method="ffill")

需说明原因。

---

# 7. 数据对齐规则

多表合并时必须明确：

join key

示例：

ts_code
trade_date

避免：

隐式 inner join 导致样本减少。

必须检查：

样本数量变化。

---

# 8. 财务数据时间点

财务数据必须考虑：

公告日期
披露日期

避免：

使用未来财务信息。

例如：

年报通常在次年披露。

---

# 9. 缓存规则

大规模数据应缓存至本地：

parquet
feather
pickle

避免：

每次运行重新调用接口。

建议：

增量更新数据。

---

# 10. 数据完整性检查

数据读取后应检查：

重复行
重复列
异常值
时间断点

示例：

drop_duplicates()

检查 index 唯一性。

---

# 11. agent行为约束

agent 不应：

假设数据天然干净
忽略缺失值
混用不同复权口径
忽略公告时间
忽略停牌影响

agent 应：

说明数据处理逻辑
保持数据时间一致性
保持字段命名稳定
避免隐式过滤样本
